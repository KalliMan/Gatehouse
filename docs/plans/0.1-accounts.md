# 0.1: Gatehouse.Accounts (provider sign-in and account emails) and one release tag per package

## 1. Goal

Create the second package, `Gatehouse.Accounts` 0.1.0: sign-in with Google, Microsoft, Facebook and GitHub on top of ASP.NET Core Identity, and the sender of Identity's account emails (links to frontend pages, SMTP or log delivery). The code is the merged, app-neutral version of What2Eat's and MDBNavigator's copies. Also: releases get one git tag per package.

Not in this plan: switching What2Eat or MDBNavigator to the package; Identity options, the session cookie, email templates, a daily email cap, account-page endpoints (link or unlink a provider, set a password). These stay in the apps.

## 2. Decisions

Made with the owner on 2026-11-24:

- **Scope:** provider sign-in plus account emails. Each app keeps everything else and plugs in through small hooks.
- **Existing unconfirmed account with the same email** (a stranger may have registered the address first): an option `UnconfirmedAccountWithSameEmail`. The default is `TakeOver`, What2Eat's rule: the provider-verified owner gets the account and its password is removed. `Refuse` is MDBNavigator's rule.
- **The app builds the emails.** The package hands the app the kind of email, the user, the address and the frontend link; the app returns subject, HTML and text (or nothing). The language of an email is the app's job too: the app's composer is resolved in a scope per email and can read the user's saved language or the request's `Accept-Language` (`IHttpContextAccessor` still works there). This is how What2Eat keeps its English and Bulgarian emails.
- **One git tag per package:** `captcha-v0.1.1` publishes only `Gatehouse.Captcha` 0.1.1, `accounts-v0.1.0` only `Gatehouse.Accounts` 0.1.0. The old `v*` trigger goes away. The nuget.org trusted-publishing policy names the workflow file (`release.yml`), which stays, so it keeps working.

Made in this plan:

- **Merged sign-in rules.** Taken from MDBNavigator, missing in What2Eat:
  - Google's "email verified" flag is read under both names Google uses (`email_verified`, `verified_email`).
  - GitHub sign-in, with the `user:email` scope. GitHub counts as verified because that scope gives only the primary verified address.
  - An account that is already linked to the provider may sign in even while its email is unconfirmed: the provider vouches for the person.
  - The stricter return-URL check (no backslash, whitespace or control characters).
  - SMTP sets the Message-Id from the sender's domain instead of the server's host name.

  Taken from What2Eat, missing in MDBNavigator:
  - Facebook sign-in.
  - Disabled accounts, through the `CanSignInAsync` hook.
  - Display names: the provider's name is passed to the app's `CreateUser` hook.
  - A separate email kind for confirming an email change.
  - The `From` override and extra headers on an email.
- **Microsoft and Facebook emails count as unverified** (Microsoft work accounts can carry addresses nobody checked).
- **New accounts from an unverified provider** get an unconfirmed email unless `ConfirmUnverifiedEmailOfNewAccounts` is true. The default (false) is MDBNavigator's safer rule. What2Eat will set it to true when it switches, because it deletes unconfirmed accounts after some days.
- **New:** a locked-out account is refused on every provider path (both apps skipped the check when linking by email).
- **Generic over `TUser : class`**, no key type. The package confirms an email through `UserManager` (generate a confirmation token, then confirm), so it never touches `EmailConfirmed` itself. The app's `CreateUser` hook builds the new user object (user name, email, its own fields); the package saves it.
- **Hooks are an abstract class** (`ExternalAccountHooks<TUser>`), not an interface, so later versions can add members with defaults without breaking apps.
- **Config keys:**
  - Providers: `Authentication:{Google|Microsoft|Facebook|GitHub}:ClientId` and `ClientSecret`, as in both apps. A provider is on only when both are set.
  - Email: section `Email`, as in What2Eat: `Delivery`, `FrontendBaseUrl`, `FromAddress`, `FromName`, `ConfirmEmailPath`, `ResetPasswordPath`, `Smtp:Host`, `Smtp:Port`, `Smtp:Username`, `Smtp:Password`. MDBNavigator's `AppBaseUrl` becomes `FrontendBaseUrl` when it switches.
- **`Email:Delivery` defaults to `None`** (MDBNavigator): nothing is sent and a warning is logged per email. `Log` is allowed in Development only, as in both apps. What2Eat must set `Smtp` explicitly when it switches (its own default was `Smtp`).
- **`IEmailDelivery` is public and registered by the package,** so apps send their other emails (newsletters, alerts, notices) through the same SMTP settings.
- **Fixed routes with defaults,** as both apps use them: providers return to `/api/auth/signin-{provider}`; endpoints under `/api/auth/external`; errors go to `/login?error=…`. All of them can be changed in code.
- **No rate limiting and no captcha inside.** The `Map…` methods return builders, and the app adds its own.
- **Dependencies of `Gatehouse.Accounts`:** the ASP.NET Core shared framework, plus
  - `Microsoft.AspNetCore.Authentication.Google`, `.MicrosoftAccount` and `.Facebook` 10.0.14 (MIT);
  - `AspNet.Security.OAuth.GitHub` 10.0.0 (Apache-2.0);
  - `MailKit` 4.18.2 (MIT).

  These are the versions both apps use. `CLAUDE.md`'s dependency rule is updated to list them.
- **One namespace,** `Gatehouse.Accounts`.
- **Logging:** never an email address, token or code, except in `LogEmailDelivery`, which exists to show the email in Development and is refused at startup elsewhere.
- **Breaking change for the repository, not for a package:** the release tag format. Written in `CHANGELOG.md` and `CLAUDE.md`.

### Behavior, sign-in

**`AddGatehouseExternalSignIn`:**

- Builds an `ExternalSignInOptions`, applies `configure`, and throws `InvalidOperationException` naming the property when `LoginPath` or `CallbackPathPrefix` does not start with `/`.
- Registers the same `configure` with `services.Configure<ExternalSignInOptions>`.
- Calls `services.AddAuthentication()` and `ExternalProviderSetup.Add`.
- Registers `new ExternalProviderList(names)` as a singleton.
- Registers `ExternalAccountHooks<TUser>` → `THooks` (scoped) and `ExternalSignIn<TUser>` (scoped).

**`ExternalProviderSetup.Add`:** for each provider in the order Google, Microsoft, Facebook, GitHub, read `Authentication:{Name}:ClientId` and `ClientSecret`. When either is blank, skip the provider. Otherwise add it and configure, as What2Eat's `Configure` does today:

- `ClientId`, `ClientSecret`
- `SignInScheme = IdentityConstants.ExternalScheme`
- `CallbackPath = CallbackPathPrefix + name.ToLowerInvariant()`
- `CorrelationCookie.SameSite = Lax`
- `OnAccessDenied` → redirect to `{LoginPath}?error=external-cancelled`
- `OnRemoteFailure` → redirect to `{LoginPath}?error=external-failed`

In both events, read `LoginPath` from `IOptions<ExternalSignInOptions>` through `context.HttpContext.RequestServices`, then call `HandleResponse()`.

Per provider:

- **Google:** `ClaimActions.MapJsonKey(EmailVerifiedClaim, "email_verified")` and `MapJsonKey(EmailVerifiedClaim, "verified_email")`.
- **GitHub:** `Scope.Add("user:email")`.

Returns the added names in ordinal order.

**`IsEmailVerified`:**

- Google: `bool.TryParse` of the `email_verified` claim is true.
- GitHub: true.
- Anything else: false.

**`ExternalSignIn.CompleteAsync`:** `GetExternalLoginInfoAsync()`; null gives `Failed`. Otherwise `SignInAsync(info, ct)`, and in `finally` always `Context.SignOutAsync(IdentityConstants.ExternalScheme)`.

**`ExternalSignIn.SignInAsync`, in this order:**

1. **Already linked.** `linked = FindByLoginAsync(provider, key)`. When not null:
   1. `!hooks.CanSignInAsync(linked)` gives `Disabled`.
   2. `ExternalLoginSignInAsync(provider, key, isPersistent: true, bypassTwoFactor: true)`:
      - `Succeeded` → `OnSignedIn(newAccount: false)`, then `Success`.
      - `IsLockedOut` gives `LockedOut`.
      - `IsNotAllowed` (unconfirmed email): `IsLockedOutAsync(linked)` gives `LockedOut`; otherwise `SignInAsync(linked, true, provider)`, `OnSignedIn(false)`, `Success`.
      - Anything else gives `Failed`.
2. **Email.** `email = ClaimTypes.Email`; blank gives `NoEmail`. `verified = IsEmailVerified(info)`. `name` = the trimmed `ClaimTypes.Name`, null when empty. `account = new ExternalAccount(provider, email, name, verified)`.
3. **Existing account with that email.** `user = FindByEmailAsync(email)`. When not null:
   1. `!verified` gives `EmailInUse`.
   2. `!hooks.CanSignInAsync(user)` gives `Disabled`.
   3. `IsLockedOutAsync(user)` gives `LockedOut`.
   4. When `!IsEmailConfirmedAsync(user)`:
      - `Refuse` gives `EmailInUse`.
      - `TakeOver`: when `HasPasswordAsync`, `RemovePasswordAsync` (a failure gives `Failed`); then confirm the email (a failure gives `Failed`).
4. **New account.** When `user` is null:
   1. `!hooks.AllowNewAccountAsync(account)` gives `SignUpClosed`.
   2. `user = hooks.CreateUser(account)`; `CreateAsync(user)` (a failure gives `Failed`).
   3. When `verified || ConfirmUnverifiedEmailOfNewAccounts`, confirm the email (a failure gives `Failed`).
5. **Link and sign in.** `AddLoginAsync(user, info)` (a failure gives `Failed`); `SignInAsync(user, isPersistent: true, provider)`; `OnSignedIn(user, newAccount)`; `Success`.

"Confirm the email" means `GenerateEmailConfirmationTokenAsync` followed by `ConfirmEmailAsync`.

A failed `IdentityResult` is logged with its error codes only (What2Eat's `LogAccountChangeFailed`). An exception from `OnSignedInAsync` is caught and logged as a warning without personal data; the sign-in still succeeds.

**`MapExternalSignIn<TUser>`** maps a group at `prefix` and returns it:

- `GET /{provider}`: `list.Find(provider)`.
  - Null: redirect to `{LoginPath}?error=external-failed&returnTo={escaped Sanitize(returnTo)}`.
  - Else: `Results.Challenge(CreateChallenge(scheme, "{prefix}/callback?returnTo={escaped Sanitize(returnTo)}"), [scheme])`.
- `GET /callback`: `CompleteAsync(http.RequestAborted)`.
  - `Success`: redirect to `Sanitize(returnTo)`.
  - Else: redirect to `{LoginPath}?error={code}&returnTo={escaped target}`.

Both endpoints get `.ExcludeFromDescription()`. The codes:

| Result | `error` code |
|---|---|
| `NoEmail` | `external-no-email` |
| `EmailInUse` | `external-email-in-use` |
| `LockedOut` | `external-locked-out` |
| `Disabled` | `external-disabled` |
| `SignUpClosed` | `external-sign-up-closed` |
| `Failed` | `external-failed` |
| (provider event) | `external-cancelled` |

### Behavior, emails

**`AddGatehouseAccountEmails`:**

- `AddOptions<EmailOptions>().Bind(section "Email")` with these rules, then `.ValidateOnStart()`:
  - `Delivery == Log` only when `IHostEnvironment.IsDevelopment()`: "Email:Delivery 'Log' is allowed in Development only."
  - When `Delivery != None`: `FrontendBaseUrl` is an absolute http or https URL: "Email:FrontendBaseUrl must be an absolute URL."
  - When `Delivery == Smtp`: `Smtp:Host` and `FromAddress` are not blank, and `Smtp:Port` is 1 to 65535: "Email:Smtp:Host, Email:Smtp:Port and Email:FromAddress must be set for SMTP delivery."
- `IEmailDelivery` singleton, chosen by `Delivery` at resolve time (What2Eat's factory pattern).
- `TComposer` as `IAccountEmailComposer<TUser>` (scoped).
- `AccountEmailSender<TUser>` (singleton). `services.RemoveAll<IEmailSender<TUser>>()`, then `IEmailSender<TUser>` → the same instance. This way the order against `AddIdentityApiEndpoints` does not matter.

**Links.** `FrontendBaseUrl.TrimEnd('/')` + `/` + the path.

| Method | Kind | Link |
|---|---|---|
| `SendConfirmationLinkAsync` | `ConfirmEmail`, or `ConfirmEmailChange` when `changedEmail` is present | Parse the query of `WebUtility.HtmlDecode(confirmationLink)`; `{ConfirmEmailPath}?userId=&code=[&changedEmail=]` |
| `SendConfirmationAsync` | same rule | same, from the arguments |
| `SendPasswordResetCodeAsync` | `ResetPassword` | `{ResetPasswordPath}?email=&code=` |
| `SendPasswordResetLinkAsync` | `ResetPassword` | `WebUtility.HtmlDecode(resetLink)` as it is |

Build query strings with `QueryHelpers.AddQueryString`. A missing `changedEmail` key must not throw (What2Eat's `TryGetValue`). `AccountEmail.To` is the `email` argument.

**Sending.** Every send runs in `try`:

1. Create an async scope.
2. Resolve `IAccountEmailComposer<TUser>` and call `ComposeAsync(…, CancellationToken.None)`.
3. Null: log at Information "Account email ({Kind}) not sent: the composer returned none" and stop.
4. Else `delivery.SendAsync(message, CancellationToken.None)`.

Any exception is caught and logged as an error with the kind and the exception type name only, never the exception itself, because an SMTP server's answer often names the recipient: "Sending the {Kind} email failed ({ExceptionType})". The `IEmailSender` methods never throw.

**`SmtpEmailDelivery`:** What2Eat's code, with the MIME building moved into `BuildMessage`. That includes the `From` override, the headers, HTML plus text through `BodyBuilder`, port 465 → `SslOnConnect` else `StartTls`, and sign-in only when `Username` is set. Plus `mime.MessageId = MimeUtils.GenerateMessageId(from.Domain)`.

**`LogEmailDelivery`:** What2Eat's code (logs To, From, Subject, headers and the text body).

**`NoEmailDelivery`:** logs a warning "Email delivery is None: an email was not sent" and returns.

## 6. Edge cases & don'ts

- **XML docs on every public type and member,** or the Release build fails.
- **Never log** email addresses, names, tokens, codes or links. The one exception is `LogEmailDelivery`, which is Development-only by validation.
- **Never link an account by email** unless the provider is one that verifies (Google with the claim true, GitHub). This check is what stops account takeover; don't loosen it.
- **Don't set `EmailConfirmed` or the user name or email directly** on `TUser`: the package only knows `TUser : class`. Use `UserManager`.
- **Don't use `ExternalLoginSignInAsync` for an account linked by email in step 3/4:** call `SignInAsync` after `AddLoginAsync`, as both apps do.
- **Always sign out of `IdentityConstants.ExternalScheme`** after the callback, even on failure.
- **Return URLs:** every redirect target built from `returnTo` goes through `ReturnUrl.Sanitize`. In query strings, `returnTo` is escaped with `Uri.EscapeDataString`.
- **`MapIdentityApi` resolves `IEmailSender<TUser>` once from the root provider:** the sender must be a singleton and must create a scope per email for the composer.
- **No rate limiting, captcha, OpenAPI tags, account-page endpoints, email templates or daily caps** in the package.
- **No new package dependencies** beyond those listed. If something seems to need one, stop and ask.
- **Don't change `Gatehouse.Captcha`** (code or README), What2Eat or MDBNavigator.
- **The owner's uncommitted `README.md` edit** (the MDBNavigator link) stays as it is.
- **Don't run** `git commit`, `git push` or `git tag`.
