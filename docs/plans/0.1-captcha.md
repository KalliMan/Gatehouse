# 0.1: repository skeleton and Gatehouse.Captcha

## 1. Goal

Create the Gatehouse repository and its first package, `Gatehouse.Captcha` 0.1.0: the captcha code of What2Eat, made app-neutral, with tests and a release workflow.

Not in this plan: switching What2Eat or MDBNavigator to the package, and `Gatehouse.Accounts`.

## 2. Decisions

- **Source:** What2Eat's copy (`c:\Projects\Pro\What2Eat\src\What2Eat.Api\Captcha\`), because it has two ALTCHA fixes MDBNavigator lacks (expiry re-check after the key derivation, one minute of grace in the cleanup).
- **License:** MIT, `Copyright (c) 2026 KalliMan` (owner, 2026-11-23).
- **Target:** `net10.0` only. The code uses `Convert.ToHexStringLower` (.NET 9+), and both apps are on .NET 10.
- **No NuGet dependencies** in the package: only `FrameworkReference Microsoft.AspNetCore.App`.
- **Config keys stay as in both apps:** section `Captcha`, keys `Provider`, `Turnstile:SiteKey`, `Turnstile:SecretKey`.
- **New: `Captcha:Altcha` settings** (`Cost`, `MinCounter`, `MaxCounter`, `LifetimeMinutes`) with today's fixed values as defaults. Needed so tests can solve a puzzle in milliseconds, and useful for tuning.
- **The app decides the failure answer.** Default is ProblemDetails 400 with `code` `Captcha.Required` or `Captcha.Failed` (What2Eat's shape). An app replaces it through `CaptchaEndpointOptions.OnFailure`.
- **`RequireCaptcha` adds only the filter**, no OpenAPI metadata: the package can't know the status code of a custom failure answer.
- **Version from the tag.** `Directory.Build.props` has `0.0.0-local`; the release workflow passes the tag's version.
- **Publishing:** nuget.org trusted publishing from GitHub Actions, no stored API key.
- **Wire format is not covered by automated tests** (there are no reference vectors). It is unchanged from What2Eat's code, which works with the altcha 3.x widget, and is checked by hand when What2Eat switches.

### Public API (namespace `Gatehouse.Captcha`)

```csharp
public interface ICaptchaVerifier
{
    bool Enabled { get; }                                   // false with Provider None
    Task<bool> VerifyAsync(string? token, CancellationToken ct = default);   // true once per valid token
}

public enum CaptchaProvider { None, Altcha, Turnstile }

public sealed class CaptchaOptions
{
    public const string SectionName = "Captcha";
    public CaptchaProvider Provider { get; init; } = CaptchaProvider.None;
    public AltchaOptions Altcha { get; init; } = new();
    public TurnstileOptions Turnstile { get; init; } = new();
}

public sealed class AltchaOptions
{
    public int Cost { get; init; } = 5_000;             // PBKDF2 iterations
    public int MinCounter { get; init; } = 5_000;
    public int MaxCounter { get; init; } = 10_000;
    public int LifetimeMinutes { get; init; } = 10;
}

public sealed class TurnstileOptions
{
    public string SiteKey { get; init; } = "";
    public string SecretKey { get; init; } = "";
}

public sealed record AltchaParameters(
    string Algorithm, string Nonce, string Salt, int Cost, int KeyLength, string KeyPrefix, long ExpiresAt);

public sealed record AltchaChallenge(AltchaParameters Parameters, string Signature);

public sealed class AltchaCaptcha(TimeProvider time, IOptions<CaptchaOptions> options) : ICaptchaVerifier
{
    public bool Enabled => true;
    public AltchaChallenge CreateChallenge();
    public Task<bool> VerifyAsync(string? token, CancellationToken ct = default);
}

public enum CaptchaFailure { Missing, Invalid }

public sealed class CaptchaEndpointOptions
{
    public string TokenHeader { get; set; } = "Captcha-Token";
    public Func<HttpContext, CaptchaFailure, IResult> OnFailure { get; set; }   // default below
}

/// <param name="Provider">"None", "Altcha" or "Turnstile".</param>
/// <param name="TurnstileSiteKey">Only with Turnstile, else null.</param>
public sealed record CaptchaSettings(string Provider, string? TurnstileSiteKey);

public static class CaptchaCheck
{
    // null = passed, or no captcha is configured; otherwise the failure answer to return.
    public static Task<IResult?> RunAsync(HttpContext http);
}

public static class CaptchaServiceCollectionExtensions
{
    public static IServiceCollection AddGatehouseCaptcha(
        this IServiceCollection services,
        IConfiguration configuration,
        Action<CaptchaEndpointOptions>? configureEndpoints = null);
}

public static class CaptchaEndpointExtensions
{
    public static TBuilder RequireCaptcha<TBuilder>(this TBuilder builder, bool anonymousOnly = false)
        where TBuilder : IEndpointConventionBuilder;

    public static RouteHandlerBuilder MapCaptchaSettings(
        this IEndpointRouteBuilder endpoints, string pattern = "/api/captcha");

    public static RouteHandlerBuilder MapCaptchaChallenge(
        this IEndpointRouteBuilder endpoints, string pattern = "/api/captcha/challenge");
}
```

`TurnstileVerifier` and `NoCaptcha` stay `internal sealed`.

### Behavior

- **`AltchaCaptcha`:** What2Eat's code with the four constants `Cost`, `MinCounter`, `MaxCounter` and `Lifetime` read from `options.Value.Altcha`. `KeyLength` (32), `MaxTokenLength` (4096) and the algorithm name stay constants. Everything else, including the order of the checks, the final expiry re-check and the minute of grace in the cleanup, is unchanged.
- **Default `OnFailure`:** `Results.Problem(statusCode: 400, title: "Bad request", detail: ..., extensions: { ["code"] = ... })`.
  - `Missing`: code `Captcha.Required`, detail `Please confirm you're not a robot.`
  - `Invalid`: code `Captcha.Failed`, detail `The check didn't pass. Please try it again.`
- **`CaptchaCheck.RunAsync`:** verifier not enabled gives null; header named by `TokenHeader` empty gives `OnFailure(http, Missing)`; `VerifyAsync(token, http.RequestAborted)` false gives `OnFailure(http, Invalid)`; else null.
- **`RequireCaptcha`:** adds an endpoint filter that returns `CaptchaCheck.RunAsync` or calls `next`. With `anonymousOnly: true` a caller whose `User.Identity.IsAuthenticated` is true is not asked.
- **`MapCaptchaSettings`:** `GET`, returns `CaptchaSettings`; the site key only when the provider is Turnstile.
- **`MapCaptchaChallenge`:** `GET`; 404 when `AltchaCaptcha` is not registered; else sets `Cache-Control: no-store` and returns `CreateChallenge()`. No rate limiting inside: the app adds its own on the returned builder.
- **`AddGatehouseCaptcha`:**
  - binds `CaptchaOptions` from `configuration.GetSection("Captcha")` and registers `CaptchaEndpointOptions` (applying `configureEndpoints`);
  - `TryAddSingleton(TimeProvider.System)`;
  - Turnstile: throws `InvalidOperationException` when `SiteKey` or `SecretKey` is blank; registers `AddHttpClient<ICaptchaVerifier, TurnstileVerifier>` with a 10 second timeout;
  - Altcha: throws `InvalidOperationException` naming the key unless `Cost >= 1`, `MinCounter >= 0`, `MaxCounter >= MinCounter`, `MaxCounter < int.MaxValue` and `LifetimeMinutes >= 1`; registers `AltchaCaptcha` as a singleton and `ICaptchaVerifier` resolving to the same instance;
  - None: registers `NoCaptcha` as a singleton.

### Workflows

`ci.yml`: on push, pull request and manual run; checkout, setup-dotnet `10.0.x`, `dotnet restore Gatehouse.slnx`, `dotnet build Gatehouse.slnx --configuration Release --no-restore`, `dotnet test Gatehouse.slnx --configuration Release --no-build`.

`release.yml`:

```yaml
name: Release

on:
  push:
    tags: ['v*']

permissions:
  contents: read
  id-token: write   # nuget.org trusted publishing

jobs:
  publish:
    name: Pack and publish
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5

      - uses: actions/setup-dotnet@v5
        with:
          dotnet-version: 10.0.x

      - name: Version from the tag
        run: echo "VERSION=${GITHUB_REF_NAME#v}" >> "$GITHUB_ENV"

      - name: Test
        run: dotnet test Gatehouse.slnx --configuration Release -p:Version=$VERSION

      - name: Pack
        run: dotnet pack Gatehouse.slnx --configuration Release --no-build -p:Version=$VERSION --output artifacts

      - name: Sign in to nuget.org
        id: login
        uses: NuGet/login@v1
        with:
          user: ${{ vars.NUGET_USER }}

      - name: Push
        run: dotnet nuget push "artifacts/*.nupkg" --api-key "${{ steps.login.outputs.NUGET_API_KEY }}" --source https://api.nuget.org/v3/index.json --skip-duplicate
```

## 6. Edge cases & don'ts

- **XML docs:** every public type and member needs one, or the Release build fails (CS1591).
- **Don't change the ALTCHA algorithm**, the JSON field names, the signing order of the fields, or any check. Only the four values become settings.
- **Don't log** tokens, secrets or IP addresses.
- **Turnstile must fail closed:** HTTP errors, timeouts and bad JSON return false.
- **No rate limiting, no OpenAPI metadata, no shared store for used puzzles** in this version.
- **Don't reference** `Microsoft.Extensions.TimeProvider.Testing`; `FakeTime` is a six-line `TimeProvider` subclass with a settable `UtcNow`.
- **Tests must be fast:** every ALTCHA test uses `Cost = 1`, `MinCounter = 1`, `MaxCounter = 20`. `AltchaSolver` tries counters from 0 until the derived key starts with `KeyPrefix`, then builds the base64 JSON payload `{ challenge, solution: { counter, derivedKey } }` with web (camelCase) names.
- **Don't run** `git commit`, `git push` or `git tag`.

## 7. Steps

1. Repository files 1 to 8, the empty package project and the empty test project. `dotnet build Gatehouse.slnx -c Release` passes.
2. Options, `ICaptchaVerifier`, `NoCaptcha`, `AltchaCaptcha` with `AltchaCaptchaTests`:
   - a solved puzzle passes once; the same token again is refused;
   - refused after the lifetime has passed (`FakeTime`);
   - refused when a signed value is altered (cost, expiry) or the derived key or counter is wrong;
   - refused for null, empty, non-base64, non-JSON, the widget's test payload (`{"challenge":null,"solution":null,"test":true}`) and a token over 4096 characters;
   - refused by a second `AltchaCaptcha` instance (other signing key).
3. `TurnstileVerifier` with `TurnstileVerifierTests` (through `FakeHttpHandler`): `success: true` passes; `success: false`, HTTP 500 and a thrown `HttpRequestException` are refused; an empty or over-long token sends no request.
4. `CaptchaFailure`, `CaptchaEndpointOptions`, `CaptchaCheck`, `AddGatehouseCaptcha` with `CaptchaRegistrationTests`: each provider registers the right verifier; Turnstile without keys throws; each bad Altcha value throws.
5. `CaptchaEndpointExtensions` with `CaptchaEndpointTests` (TestHost): no header gives 400 with `Captcha.Required`; a bad token gives 400 with `Captcha.Failed`; a solved one gives 200; provider None gives 200 without a header; a custom `OnFailure` and a custom `TokenHeader` are used; the challenge endpoint gives 404 for None and `no-store` for Altcha; the settings endpoint shows the site key only for Turnstile.
6. READMEs, `CHANGELOG.md`, `ci.yml`, `release.yml`.
